# AI Campus「你画我猜」设计说明

## 目标

把参考项目中的完整实时多人你画我猜体验移植到当前 AI Campus。学生使用现有校园账号进入大厅、创建公开或密码房、加入房间、轮流画图和猜词，并查看得分与已完成画作。桌面端和移动端均可使用。

## 已确认的范围

- 大厅：公开房间列表、人数/状态/轮数、创建公开或私密房、邀请码加入、最近进入的房间。
- 房间：2–6 人、房主控制开始、60 秒回合、轮流作画、画笔/颜色/粗细/橡皮擦/清空、实时笔画同步、聊天猜词、系统提示、在线状态。
- 规则：只有画手收到答案；正确猜中者和画手各得 1 分；所有猜手都猜中后提前 5 秒结束；超时或跳过进入下一位；结束时展示排行榜。
- 记录：回合与最终分数可复查，已完成画作显示在记录画廊；最近房间只对当前用户可见。
- 异常：过期邀请码、满员/已结束房间、断线重连、非画手绘画、重复猜词、未登录访问均给出可操作提示。
- 校园接入：从侧栏和 3D 校园服务目录进入，保留现有登录与个人资料。

## 不在移植范围

- 不移植参考项目的 Vue/Spring Boot 以外服务、Socket.IO、Sa-Token、Redis Room 运行时、OSS 配置、重复用户认证或独立部署容器。
- 不修改私信 WebSocket 协议或现有消息会话逻辑。
- 不顺带改动校园其他服务、全局请求层和数据库既有表。

## 架构与边界

- 前端新建独立 `draw-guess` 页面与 API/socket 客户端；路由、侧栏、3D 目录仅增加入口和页面声明。
- 后端新建 `module.drawgame`，共用 `UserContext` 账号身份与一次性 WebSocket ticket 设计，但 ticket key、endpoint 和 handler 均单独命名空间隔离。
- REST 处理大厅查询、房间创建/加入/退出、上传最终作品以及权限校验；游戏 WebSocket 负责房内命令和广播。服务端校验成员、画手权限、房间状态、计时和得分，客户端不能提交分数或正确答案。
- 关系库只新增带 `draw_game_` 前缀的表和初始化词库；上传使用现有 `UploadService`。不改既有表结构、不增加端口/容器。
- 活跃房间由当前应用实例持有并以数据库记录保存可回看结果；部署为单实例时支持完整多人游戏。若今后横向多实例部署，需另行将房间运行态迁移到 Redis 并加分布式计时，此项不是本次隐性扩展。

## 事件协议（初版）

客户端消息：`draw`（一批受限坐标点）、`clear`、`guess`、`chat`、`skip`、`ready`。服务端广播：`room_state`、`round_started`、`draw`、`canvas_cleared`、`chat_message`、`guess_result`、`timer`、`round_ended`、`room_ended`、`error`。服务端在握手消费只用一次的 ticket，并从 ticket 绑定用户和房间，不信任 URL 中的用户 ID。

## 体验方向

- 页面承接校园端现有品牌蓝与中文无衬线字体。
- 大厅把一块带少量手绘涂鸦的画纸作为视觉焦点；房间将白色画布置于主列，玩家、计时与聊天置于辅助列。
- 画笔工具按绘画行为分组，倒计时只在最后 10 秒改为强调色；不添加与状态无关的装饰动画。
- 桌面保持画布优先的双栏结构；窄屏改为画布、玩家、聊天纵向排列，工具仍可触达。

```text
大厅： [标题 / 新建房 / 邀请码加入]
       [公开房列表             最近房间]
       [画作记录画廊]

房间： [回合/画手/大倒计时                     ]
       [画笔工具] [      画布      ] [玩家与分数]
       [颜色/粗细] [      画布      ] [猜词聊天]
       [离开/跳过/房主开始                      ]
```

## 兼容性与回归要求

- 所有新增后端代码、SQL、前端组件和样式均有明确 `drawgame` 或 `draw-guess` 命名空间；既有私信、导航通用请求行为不做重构。
- 新增路由必须被现有根路由和 3D 内存路由共同覆盖；新增导航数据只追加一项。
- 回归检查覆盖学生端现有全量单测/构建、管理端现有全量单测/构建、后端全量测试/编译，以及新增的房间规则、WebSocket 授权与路由行为。
- 如果基础设施或依赖下载导致某项检查不能运行，必须把环境阻塞与代码结果分开报告，不能以未运行视作通过。

## 主要风险与处理

| 风险 | 处理 |
| --- | --- |
| 猜词泄露 | 答案只投递给当前画手的个人 WebSocket 会话；其他成员状态包含遮罩词长。 |
| 客户端伪造分数/笔画越权 | 分数和答案由服务器维护，只有当前画手能发送笔画；绘图消息限制坐标数、颜色和频率。 |
| WebSocket 冲突影响私信 | 使用独立 `/ws/draw-guess`、独立 ticket key/服务/handler，不更改 `/ws/chat`。 |
| 新路由改变现有 3D 服务回退 | 增加针对新增服务和未知服务的 router 行为测试，并保持现有 path 映射不变。 |
| 画作/聊天/列表引起资源膨胀 | 每回合限制绘图事件大小；列表分页；只保存完成回合快照，不无限保存临时轨迹。 |
| 旧数据库无法自动创建新表 | 提供独立、幂等 migration，并接入项目已有 SQL 安装入口。 |
