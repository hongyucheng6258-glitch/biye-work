# 项目文档与浏览器流程验证设计

## 目标

更新项目 README 与部署说明，使其反映当前已实现并可部署的前后端状态；使用真实浏览器验证关键业务流程，同时隔离测试服务和数据，避免影响正在运行的校园平台。

## 当前情况

- 根目录 README 仍写着“等待后端环境联调”，与当前已经运行的前后端和已有测试结果不一致。
- 部署说明已有本地及 Docker Compose 步骤，也提醒生产部署移除演示数据挂载，但演示账号和测试数据用途需要在项目概览与部署步骤中保持一致。
- `tests/browser/e2e/run-all.cjs` 已覆盖 20 个类别，使用真实 HTTP 请求和浏览器；其中大多数场景创建或修改业务数据。
- `15-ai` 会调用已配置的真实 AI 服务，可能产生外部请求及费用。
- 主 Docker Compose 目前占用 8080、5173、5174，并已运行，不能用于本次写入型 E2E 测试。

## 方案

1. 给 E2E 公共配置增加可选目标地址，默认仍使用现有本地地址；本次测试配置指向另一组端口。
2. 使用单独 Compose 项目启动测试后端、学生端、管理端、MySQL 和 Redis。依靠 Compose 项目名隔离容器、网络和命名卷，避免操作主项目服务与数据库。
3. 在隔离数据卷中使用仓库演示初始化数据；为 E2E 注册账号提供临时环境变量。跳过会调用真实 AI 模型的 `15-ai` 类别，其余核心流程使用测试账号与带 `[E2E测试]` 标记的数据。
4. 更新 README 的项目状态和测试入口；更新部署说明中的本地/Docker 运行步骤、测试配置、演示数据说明及生产环境禁用规则。
5. 执行隔离 Compose 健康检查、核心浏览器流程，并运行现有无后端写入的浏览器交互脚本；结果只报告真实观察到的通过、失败、阻塞和跳过类别。

## 安全边界

- 不停止、重建或改写当前 `ai-campus` Compose 项目。
- 不连接或清理当前项目数据库；测试数据只写入隔离的 E2E MySQL 卷。
- 不配置 AI API 密钥，不执行 `15-ai`。
- 不删除测试或业务文件，不更改业务功能和数据库结构。
- 测试账号密码只通过进程环境变量传递，不写入仓库或测试报告。
- 测试结束后只停止并移除本次独立 Compose 项目及其专用卷；不得使用不带项目限定的全局清理命令。

## 验收标准

- README 与部署说明不再包含过时的“等待后端联调”状态，并明确区分开发/测试数据与生产数据。
- E2E 地址能通过环境变量指向隔离端口，同时保留原有默认值。
- 隔离服务健康后，所选核心浏览器流程可执行，且主 Compose 项目服务和数据保持原状。
- 报告准确标出运行、失败、阻塞和跳过的测试类别；不把未执行的 AI 外部调用表述为通过。

## 非目标

- 本次不改造业务页面或后端逻辑。
- 本次不承诺覆盖真实 DeepSeek 调用、生产环境浏览器兼容性或上线级负载测试。
- 本次不上传代码、发布镜像或修改线上部署。
