# 新页面继承底部滚动位置的修正

2026-09-29，用户反馈打开不同内容后总是显示页面底部。沿用 `feat/tongpin-ui-redesign` 分支。

## 原因与复现

学生端使用 Vue Router 的单页切换，但没有配置窗口滚动规则。列表切换到详情不会创建新文档，旧窗口位置继续保留；详情比列表短时，浏览器把位置限制到新的最大滚动范围，因此落在底部。

真实 Docker 浏览器复现：1440px 视口的闲置列表滚到 1181px，点击下方物品后，详情停在 710px；详情总高 1610px、窗口高 900px，710px 正好是底部。记录中没有页面切换后的 `window.scrollTo` 调用，当前焦点也不是底部输入框。修正前探针按预期失败：`New detail page inherits previous scroll position: 710px`。

## 修正范围

这是后续页面显示缺陷的专项修正，涉及窗口滚动行为，不能仅用 CSS 可靠解决。

- 新增 `web/frontend/student/src/ui/route-scroll.mjs`，只管理文档窗口的阅读位置。
- 在学生端 `src/router/index.js` 中只新增该策略的 import 和 `scrollBehavior` 配置。
- 新打开不同路径时回到顶部；浏览器前进/后退使用历史记录中的阅读位置。
- 返回异步列表时，等待内容高度足够后恢复，避免在加载占位阶段把位置截断；最多等待 3 秒，内容失败或永久变短时允许浏览器限制到可用范围。
- 后续导航发生后，较早的待恢复位置不能覆盖新页面。
- 同一路径的筛选、分页、个人中心标签等 query 变化保留窗口位置；显式 hash 锚点仍可使用。
- 不改聊天消息区、AI 对话区、游戏消息区及 3D 工作区的内部滚动行为。

没有修改路由表、path/name/meta/props/redirect、鉴权守卫、业务 API、状态管理、现有 Vue 脚本或已有测试。

## 验证

- 原学生端测试 80/80 通过，新增独立滚动策略测试 6/6 通过；覆盖顶部、历史恢复、query、锚点、异步高度和过期恢复取消。
- 真实浏览器 390/1440/1920px 共 27 次位置测量：从列表下方打开详情均为 0px；底部导航切换活动、个人中心、闲置均为 0px；返回列表恢复到 4079/1181/1181px；导航弹窗关闭前后均保留 350px。
- 浏览器运行时错误 0。
- 学生端生产构建通过，既有依赖和包体积警告保留。
- `git diff --check` 通过。
- **原冻结审计没有修改或换基准。** 它按原 CSS 任务边界报告 2 个差异：学生端路由入口的展示配置，以及新增窗口滚动模块。本次不将该结果描述成原审计全通过。
- `node scripts/verify-route-scroll-compatibility.mjs` 单独检查：路由入口必须与原基准完全一致，仅允许准确的一行 import 和一项滚动配置；原审计输出必须恰好是上述 2 个差异，其余 505 个受保护文件及 83 个 Vue 契约均保持。任何额外差异都会失败。
