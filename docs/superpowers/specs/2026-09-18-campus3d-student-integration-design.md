# 学生端 3D 校园空间入口设计

## 目标

在 `Ai-campus` 学生端增加“3D校园”入口，将现有 `corridor.html` 的三维中庭、走廊和房间交互接入 Vue 学生端。3D 页面只承担空间探索和服务导航；活动、闲置、问答、AI 学习等业务继续使用学生端已有的 2D 页面和接口。

## 范围

包含：

- 首页、桌面导航和移动端菜单中的“3D校园”入口。
- `/campus-3d` 独立 3D 页面。
- 中庭、三条走廊、11 个服务房间和原型中的场景细节。
- 鼠标拖动、WASD/方向键、门牌点击、房间内移动、全屏、地图和舒适模式。
- 进入房间后的提示面板，以及点击屏幕/服务台后进入已有学生端页面。
- 房间返回、回到门口、回到首页和浏览器返回后的空间状态恢复。
- Three.js 初始化失败时的提示和已有 2D 页面降级入口。

不包含：

- 新增第二套 2D 服务目录或分页。
- 复制原型中的演示服务工作区和演示业务数据。
- 修改现有活动、闲置、问答、AI 等业务页面的功能和接口。
- 修改后端数据库或 API。

## 入口和路由

新增公开路由：

```text
/campus-3d
```

首页 Hero、`MainLayout` 桌面导航和移动端抽屉均通过 Vue Router 进入该路由。3D 页面使用独立沉浸式布局，提供返回学生端首页的按钮。

## 空间层迁移

从原型迁移空间层到 `web/frontend/student/src/features/campus3d/`：

- `campus-scene.js`：Three.js 场景、相机、移动、门、房间和清理生命周期。
- `campus-data.js`：服务 ID、分区、房间标题和主题颜色。
- `three.module.js`：沿用原型使用的 Three.js r160 本地模块，避免 CDN 依赖。

空间层不渲染业务页面，只通过回调通知 Vue：

- `onEnter(serviceId)`：进入房间。
- `onRoomInteract(serviceId)`：点击屏幕或服务台。
- `onNavigate(state)`：移动和过渡状态。
- `onPosition(state)`：当前位置。
- `onError(error)`：WebGL 或初始化错误。


点击房间内容后调用现有路由。现有页面继续使用自己的登录守卫、接口和业务状态。

## 交互流程

1. 用户从学生端进入 `/campus-3d`。
2. 场景加载完成后显示中庭。
3. 用户点击门牌或通过地图选择服务，移动到对应房间。
4. 进入房间后只显示房间提示，不自动跳转。
5. 用户点击房间屏幕、服务台或“打开服务”按钮，进入对应已有 2D 页面。
6. 浏览器返回或点击返回按钮后恢复到进入前的房间和相机位置。
7. 点击“回到门口”才离开房间；点击“返回首页”离开 3D 页面。

原型中的 2D 切换按钮和 2D 目录不迁移到学生端 3D 页面，因为学生端已经有对应页面。

## 状态恢复

进入业务页面前，将以下内容存入 `sessionStorage`：

- 当前服务 ID。
- 相机位置、yaw 和 pitch。
- 当前是否在房间内。
- 当前场景模式和来源路径。

重新进入 `/campus-3d` 时恢复合法状态；状态失效时回到中庭。组件卸载时销毁 Renderer、动画帧、ResizeObserver、键盘和指针监听。

## 视觉与兼容

3D 页面沿用学生端蓝白设计 Token，保留原型的玻璃面板、校园蓝、分区色、导览地图和全屏按钮。桌面端使用悬浮提示面板，移动端使用底部提示面板。WebGL 不可用时显示错误提示，并提供跳转到已有 2D 首页服务的入口。

## 验证

- `npm test`
- `npm run build`
- 首页、桌面导航、移动菜单均能进入 3D 页面。
- 3D 场景可加载，三条走廊和 11 个房间可导航。
- 房间内容不会自动打开，屏幕和服务台可触发对应路由。
- 活动、AI 答疑、错题本至少完成一次进入、打开、返回和退出验证。
- 浏览器返回后恢复房间和视角。
- 全屏、导览地图、舒适模式和移动端布局可用。
- WebGL 失败时可进入已有 2D 页面。

## 取舍

不使用 iframe 嵌入 `corridor.html`，避免静态原型与 Vue 路由、登录守卫和返回状态分离。只迁移空间层，业务内容全部复用学生端已有实现，降低重复代码和数据不一致风险。
