# 管理端侧栏分组折叠设计

## 背景

管理端左侧导航目前按“概览、内容审核、内容管理、用户与社区、系统”分组显示，但所有分组和菜单项始终展开。页面较长时，管理员需要滚动较长距离才能找到靠下的入口。

## 目标

让管理员可以按分组收起和展开侧栏菜单，减少纵向占用，同时保留现有页面入口、路由、权限过滤和待处理数量提示。

## 交互方案

- 每个分组标题作为可操作的折叠按钮，并显示清晰的展开/收起指示。
- 同一时刻至多展开一个分组。点击已展开的分组会将其收起；点击其他分组会收起当前分组并展开目标分组。
- 初次进入时，自动展开当前路由所属的分组；切换到另一个分组中的页面后，自动展开新路由所属分组。
- 用户手动收起当前路由所在分组时，保持收起状态，直到用户展开其他分组或路由切换到另一个分组。这样不会因路由更新立即覆盖用户刚才的操作。
- 当前分组内已有的激活态、图标、待处理数量徽标和管理员权限过滤保持原样。
- 分组收起时不显示其子菜单项；顶栏现有的汇总待办提示保持不变，不新增可能重复计数的汇总数字。

## 窄屏行为

保留当前 920px 以下侧栏的图标栏布局。此布局中分组标题和文字本来就隐藏，所有现有图标入口继续可见且可访问；折叠交互只作用于桌面完整侧栏，避免在窄屏隐藏页面入口。

## 无障碍与视觉

- 分组标题使用原生按钮语义，支持鼠标和键盘操作。
- 使用 `aria-expanded` 表示状态，并关联对应的子菜单容器。
- 展开指示与状态同步；增加过渡效果时尊重减少动态效果设置。
- 复用当前侧栏颜色、间距和字体规范，展开态及激活态保持足够对比度。

## 范围与约束

- 修改范围限定在管理端侧栏布局及其样式/局部状态。
- 不修改路由定义、页面内容、权限判断、登录流程、接口、数据和后端服务。
- 不新增全局侧栏收窄开关，也不持久化折叠偏好；本次只实现分组折叠。

## 验收条件

1. 桌面侧栏中点击任意分组可以展开或收起；展开另一组时前一组自动收起。
2. 直接进入某个子页面时，其所属分组默认展开，当前菜单仍有原有激活样式。
3. 组内全部原有导航项、图标、徽标及权限过滤结果不变，点击后仍进入原页面。
4. 920px 以下仍显示原有图标栏入口，不因折叠隐藏任何导航入口。
5. 键盘可以聚焦并操作分组按钮，辅助技术可读取展开状态。
6. 变更仅限侧栏呈现与局部交互，不影响登录、页面路由或业务数据。

## 自查

- 设计符合用户确认的“一次展开一个分组”交互。
- 覆盖了直接访问深层路由、手动收起当前组、窄屏图标栏和待办数量等现有行为。
- 明确排除了全局收窄开关、偏好持久化及其他业务修改，便于实现时控制回归范围。
