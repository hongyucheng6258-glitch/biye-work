## 确认的缺陷与复现方法

### B01 · P1：收藏深链初始化没有加载数据

先在闲置详情收藏，直接打开 `/profile?tab=favorite`。收藏列表为空；先进入普通个人页再点击收藏标签能够加载。`Profile.vue` 的标签监听调用 `loadFavorites()`，但初始挂载只加载闲置/举报等数据，不会触发已激活收藏标签的监听。

代码：`web/frontend/student/src/views/profile/Profile.vue:202`、`:238`。证据：[收藏深链](evidence/full-browser-qa/failure-65.png)。正常切换标签后加载、取消收藏已通过，因此不是收藏接口整体不可用。

### B02 · P1：动态评论图标没有可调用处理函数

进入已发布动态，点击评论图标，评论区不展开。模板绑定 `toggleComments(p)`，脚本未定义该函数；已有的 `openPost(p)` 能展开评论。评论提交、回复、删除和分页无法从此入口验收。原冻结基线也有该绑定，不能将本问题直接归因于本次 UI 修改。

代码：`web/frontend/student/src/views/social/PostSquare.vue:82`。证据：[评论入口](evidence/full-browser-qa/bug-social-comment.png)。

### B03 · P1：活动详情的报名名单管理将鼠标事件作为页码

发布者进入活动详情，点击“报名名单管理”。网络请求包含 `pageNum=[object PointerEvent]`，业务响应 `code=400`、参数格式错误。模板直接绑定 `loadMembers`，函数的首个参数本意为页码，点击事件覆盖了默认值。“我的报名→我的发布→报名管理”入口能正常审批，已用同意/拒绝验证。

代码：`web/frontend/student/src/views/activity/Detail.vue:81`、`:340`。证据：[详情名单请求](evidence/full-browser-qa/bug-activity-members.png)。

### B04 · P1：后台编辑管理员时留空密码无法保存

新建隔离审核员后点击编辑，只修改昵称，密码按页面“留空则不修改”的提示保持空白，点击保存。后端返回 `code=400`、密码不能为空。新增和编辑共用的 `AdminSaveDTO` 对密码应用 `@NotBlank`。填写明确密码后编辑可成功并重新登录，但不符合页面所承诺的留空行为。

代码：`web/backend/src/main/java/com/campus/platform/module/admin/dto/AdminSaveDTO.java:16`。证据：[管理员编辑](evidence/full-browser-qa/failure-130.png)。本次没有改动 DTO 或密码规则。

### B05 · P2：后台全局搜索跳转后不应用关键词

按 Ctrl+K，输入测试学号，回车。地址跳到 `/admin/user?q=...`，用户筛选输入框仍为空，数据未按关键词筛选。用户列表 `keyword` 初始为空且没有从路由读取 `q`。列表内手动输入学号并搜索可正常筛选。

代码：`web/frontend/admin/src/views/user/UserList.vue:52`。证据：[全局搜索](evidence/full-browser-qa/bug-admin-global-search.png)。

### B06 · P1：AI 提纲接口成功后页面丢弃结果

错题本点击“生成薄弱点报告”。接口 `/ai/outline` 返回 `code=200`，`data` 是 1203 字符的实际模型输出字符串。组件读取 `res.answer` 得到 `undefined`，加载结束后重新出现生成方式，没有结果。AI 复习计划、讲解和同类题等其他成功路径已通过。

代码：`web/frontend/student/src/views/ai/components/WrongOutlineDialog.vue:110`。证据：[提纲未展示](evidence/full-browser-qa/failure-248.png)，响应类型/长度在 `results.json.outlineDiagnostic`。报告只统计模型成功响应的观测，不将错误预期测试算作模型故障。

### B07 · P1：AI 请求中切换场景使发送按钮一直禁用

在 AI 答疑发送较长问题，立即切换“校园向导”，输入另一个问题。等待 8 秒仍不可发送。`cancelStream()` 中止旧请求并增加 `requestSeq`，未重置 `asking`；旧请求收尾因序号失效也不重置它。独立刷新并进入向导/PDF 后均可成功回答，证实不是模型不可用。

代码：`web/frontend/student/src/views/ai/ChatView.vue:129`、`:160`、`:361`。证据：[切换场景锁死](evidence/full-browser-qa/bug-ai-cancel-scene.png)。一次接续 PDF 检查被此问题阻断，已单列 BLOCKED；独立 PDF 成功路径另有 PASS。

### B08 · P2：聊天主操作区域首屏不完整，私信输入区被底部导航覆盖

AI 对话的输入区在 1440×900 首屏下方 `y=1072.78`，390×844 下为 `y=1495.56`；手机私信输入区 `y=963.19`。桌面私信输入区 `y=808.19..891.19` 与底部导航 `y≈838..892` 重叠。滚动使输入区可操作的检查通过，但这不能抵消聊天首屏缺少完整主操作区域的问题。

代码：`web/frontend/student/src/views/ai/ChatView.vue:726`，`web/frontend/student/src/views/chat/ChatRoom.vue:160`，底部导航 `web/frontend/student/src/layout/MainLayout.vue:1164`。测量见 `results.json.regionChecks`。
